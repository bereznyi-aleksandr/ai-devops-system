# P1. Простой Telegram-бот: меню, ответы, форма заявки, выгрузка

## 1. Что делает бот

Бот малого бизнеса. Клиент открывает меню, читает услуги, цены и контакты и оставляет заявку.
Владелец получает уведомление о каждой заявке и выгружает все заявки файлом CSV.

## 2. Требования

- R1 Меню. На `/start` бот отвечает приветствием и кнопками «Услуги», «Цены», «Оставить заявку»,
  «Контакты». Кнопки — обычная клавиатура или встроенные кнопки, на выбор рабочего.
- R2 Ответы. «Услуги», «Цены», «Контакты» отвечают текстом из файла содержимого (`CONTENT_PATH`,
  JSON с ключами `services`, `prices`, `contacts`). Текст в коде не зашит.
- R3 Форма заявки. «Оставить заявку» спрашивает по очереди имя, телефон, комментарий. Телефон —
  от 10 до 15 цифр, допускаются `+`, пробелы, скобки и дефисы. Неверный телефон — повторный вопрос,
  заявка не сохраняется. В конце — подтверждение с номером: «Заявка №<n> принята».
- R4 Уведомление. После сохранения бот пишет в чат владельца (`ADMIN_CHAT_ID`) имя, телефон и комментарий.
- R5 Выгрузка. `/export` из чата владельца — файл `applications.csv` (UTF-8, заголовок
  `id,created_at,chat_id,name,phone,comment`). Из другого чата — отказ текстом, файла нет.
- R6 Хранение. Заявки — в SQLite по пути `DATABASE_PATH`; после перезапуска бота они на месте.
- R7 Безопасность (угрозы T1, T5 протокола). Текст клиента — данные: бот его сохраняет и показывает,
  но не исполняет. Значение токена не попадает ни в одно сообщение, файл или журнал. Бот вызывает
  только методы `getMe`, `deleteWebhook`, `getUpdates`, `sendMessage`, `sendDocument`,
  `answerCallbackQuery`, `setMyCommands`. Каждый экземпляр — своя база: заявки одного владельца не
  видны другому.
- R8 Настройка — только переменными окружения: `BOT_TOKEN`, `TELEGRAM_API_BASE`
  (по умолчанию `https://api.telegram.org`), `ADMIN_CHAT_ID`, `DATABASE_PATH`, `CONTENT_PATH`.
  Получение обновлений — длинный опрос `getUpdates`.
- R9 Запуск одной командой из `package.json` (`npm start`) или `python -m bot`; зависимости закреплены
  файлом блокировки.

## 3. Приёмка (E5-4)

Команда: `node acceptance/p1_acceptance.mjs --cmd "<команда запуска бота>" --cwd <папка продукта>`.
Сценарии A1–A8 на заглушке Bot API; итог `P1_ACCEPTANCE=PASS` только если прошли все.

| Сценарий | Требование | Проверка |
|---|---|---|
| A1 | R1 | `/start` → приветствие и четыре кнопки |
| A2 | R2 | «Услуги», «Цены», «Контакты» → текст из файла содержимого |
| A3 | R3, R4 | заявка: имя → телефон → комментарий → «Заявка №…»; владелец получил уведомление |
| A4 | R3 | неверный телефон → повторный вопрос; заявка не сохранена |
| A5 | R5 | `/export` владельца → CSV с заявкой; чужой чат → отказ, файла нет |
| A6 | R7 | комментарий-внедрение сохранён как текст; токена нет ни в одном вызове; методы только из списка |
| A7 | R6 | перезапуск → `/export` всё ещё содержит заявку |
| A8 | R7 | два экземпляра с разными базами и токенами: выгрузка B не содержит заявок A |
