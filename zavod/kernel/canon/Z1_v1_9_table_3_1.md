## 3.1. Соответствие ролей Завода каноническим ролям H1.31 §16 (1:1)

Названия «директор …» — только удобные имена. Права и запреты берутся из канонической роли;
своих прав имя не добавляет. Роль, которой нет в этой таблице, запрещена до решения оператора.

| Роль Z1 | Каноническая роль H1.31 §16 | Разрешено (белый лист канона) | Запрещено (канон) |
|---|---|---|---|
| Оператор | Оператор | цель, риск, бюджет, статика ГД, разрешение на выпуск, `OPERATOR-GATE-H14-01` | быть передатчиком сообщений |
| Генеральный директор | Генеральный директор | стратегия, направления, контракт директору, общие правила, приём опыта | выполнять техническую задачу вместо контура |
| Директор производства | Куратор ГД / ДИР направления «производство» | интервью, разбивка на задачи, дашборд, сверка с брифом | писать состояние напрямую, утверждать собственный бриф |
| Директор качества и безопасности | Контур C2 уровня ДИР | правила уровня, разбор ошибок, контракты подчинённым | проверять причину ошибки, если сам её автор |
| Директор продукта и продаж | Куратор ГД / ДИР направления «продукт» | интервью, разбивка, дашборд, сверка с брифом | писать состояние напрямую, утверждать собственный бриф; обещания покупателю — только через решение оператора |
| Куратор рабочих | Куратор рабочих контуров | граф задач, контуры, ветки-песочницы, системный тест | обходить решение Kernel о готовности |
| Аналитик, Исполнитель | Аналитик / Исполнитель | план, критерии, код в своей ветке | утверждать собственный результат |
| Аудитор | Аудитор контура; для выпуска — Аудитор итогового предмета (§9) | вердикт с обоснованием по одному `head_sha` | быть в `subject_author`; исправлять работу незаметно |
| Kernel, Egress, доставщик, сторож | одноимённые технические роли §16 | как в каноне | как в каноне |
| Надзиратель ограждения (`src/fencer.mjs`) | Оператор — как его инструмент: работает только под входом оператора с полномочием `OPERATOR` (роль БД `bem_governance`), своих прав не имеет | запустить попытку отправки в своей единице исполнения; погасить единицу целиком; после пустой единицы — `record_outbox_fence` | писать что-либо ещё; выполнять отправку; работать под входом Kernel, рабочего или без полномочия `OPERATOR` |

Проверка: машинный список ролей Kernel (этап 4) сверяется с этой таблицей; неизвестное имя роли
и любое право сверх канона — отказ (тест E4-7).
Надзиратель (ответ на аудит Z5 M-Z5-02): запись ограждения открывает сверке путь
`CONFIRMED_NOT_SENT`, а это акт оператора, как и сама сверка. Поэтому `record_outbox_fence` требует
то же, что `reconcile_unknown_outcome`: собственный вход с действующим полномочием `OPERATOR`
(`assert_authority`). Точный список вызывающих: `EXECUTE` есть только у `bem_control_owner` и
`bem_governance`; самопроверка расширения и итоговая проверка 05 отклоняют любое лишнее право;
Kernel и рабочие получают отказ `42501`.
