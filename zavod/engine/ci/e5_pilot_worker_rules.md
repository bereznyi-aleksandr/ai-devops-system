# Правила рабочего пилота P1

1. Репозиторий: `bereznyi-aleksandr/zavod-p1-bot`. Ветка: `zavod/p1-<первые 8 знаков work_item_id>` от `main`.
   В `main` не писать никогда. Слияние и выпуск делает Завод, не рабочий.
2. Язык: Python 3.11+, только стандартная библиотека (`sqlite3`, `urllib.request`, `json`, `csv`, `threading`).
   Сторонних пакетов нет. Пакет `bot/` с `bot/__main__.py`; запуск `python -m bot` из корня репозитория.
3. Файл `requirements.lock` в корне: одна строка `# stdlib only: no third-party dependencies` (R9: файл блокировки).
4. Настройка — только переменные окружения R8. Токен берётся только из `BOT_TOKEN` и никуда не пишется:
   ни в сообщения, ни в файлы, ни в журнал, ни в текст ошибок (адрес запроса с токеном не печатать).
5. Получение обновлений — длинный опрос `getUpdates` (таймаут 25–30 с); при старте — `deleteWebhook`.
   Методы Bot API — только список R7. Ошибка сети — пауза и повтор, бот не падает.
6. Тесты: `tests/` без сети, запуск `python -m unittest discover -s tests`. Проверить телефон (R3), CSV (R5),
   хранение (R6), что текст клиента сохраняется как есть (R7).
7. Не трогать: `.github/`, `.claude/`, `CLAUDE.md`. Изменение этих путей — провал системной проверки.
8. Секретов, ключей и платных SDK в репозитории нет; файл `.env` не создавать.
9. Последний коммит ветки добавляет `WORKER_DONE.txt`: work_item_id, что сделано (до 10 строк), итог
   `python -m unittest discover -s tests` (число тестов и OK/FAIL). Без этого файла работа не считается сданной.
10. Приёмка A1–A8 и живая проверка идут после сдачи на стороне Завода. Рабочий их не запускает и не правит.
